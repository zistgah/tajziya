## 0.6.0

- Work packets. `packets/` holds 148 small pieces of work any AI or person can take, each with
  its inputs, the files it must produce, its licence rule and one acceptance command,
  `python3 -m tajziya packet check <ID>`. Six kinds of check, all mechanical: sutra tables,
  implementation maps, script tables on Romenagri's pivot, the Romenagri pin, the browser
  build's parity, and corpora. The landing page opens with them, grouped by area, each with a
  claim link; `.github/workflows/packets.yml` runs the packets a pull request touches and the
  gate, so a pull request is judged without anyone reading it.
- Romenagri, the author's transliteration system, vendored byte for byte from
  hindawiai/chintamani's Romenagri folder (pinned) and offered as functions:
  `tajziya.romenagri.roman()` and `devanagari()` run his own pipeline from mass_hindawi. Every
  sutra's Romenagri form is in `modules/cls/data/romenagri/sutras.tsv`; 3,609 of 3,983 come back
  the same, the rest lose the avagraha, which is packet PKT-ROM-01.
- The review page gives every sutra an issue link and its Romenagri form, and points to the
  packets that will add translations, interpretations, implementing code and scripts.
- The landing page links the review, the coverage and the packages; V25 refuses a page in
  `docs/` it does not link. V24 rebuilds Romenagri and checks the committed forms; V26 checks
  every packet. `CORPUS.md` is the corpus work order the corpus packets follow.

## 0.5.0

- The Sanskrit parser's sutra database, complete. All 3,983 sutras come from the data that
  powers ashtadhyayi.com, whose terms allow use with credit, which `modules/cls` gives
  (`data/LICENSES/ashtadhyayi-com.txt`). Each sutra carries its type, the term a samjna
  defines, its padaccheda and its Siddhanta Kaumudi number, in Devanagari.
  `tools/sutra_import.py` derives `data/ashtadhyayi/sutraani.tsv` from a pinned checkout.
- `rules()` returns these full records. The 64 adhikara sutras are typed as such.
- The author's source review of 5 Oct 2026 is folded in: its 53 disagreements with the
  sanskritdocuments.org compilation, on 47 sutras, are recorded by sutra and field in
  `data/review/flags.json`. That compilation's text stays local, under its terms.
- A second open source checks the text: vidyut-prakriya's sutrapatha (MIT), transliterated
  from SLP1, agrees on 3,975 of 3,983 sutras; the 8 it does not are flagged.
- `docs/review.html`, generated by `tools/review_gen.py`, lists every sutra, flags the 55
  that disagree, and opens a pre-filled issue for each on zistgah/tajziya. `--local FILE`
  writes a private copy with your local compilation's values beside the open ones. V23 keeps
  the page current.
- `registry/licences.json` accepts ashtadhyayi.com's terms with their notice.

## 0.4.0

- Every language and script the project-ilm 3D explorer shows. `registry/ilm/` holds a pinned,
  verbatim copy of the ILM registry the explorer draws (project-ilm/ilm.codes at c49f529): 7,867
  ISO 639-3 languages and 226 ISO 15924 scripts. The 7,787 languages no poster node holds become
  coverage nodes; every one conforms, refusing by name, with package P-PROF-01 (the language
  profile) named where the posters' lineage would be.
- Script modules. A script is a module of its own kind, with two layers (L1 pivot, L2
  orthography), bound in `registry/script_bindings.json` and judged by the same acceptance test.
  Every script stands in a script frame until a module is bound for it.
- `tools/langpack.py --ilm`, `--scripts` and `--everything`: 8,091 packages (78 poster languages,
  7,787 explorer languages, 226 scripts), each accepted as handed over, in three bundles.
- `tajziya coverage`: counts and conformance for the explorer's languages and scripts.
  V21 runs it; V22 builds and accepts a sample of explorer languages and every script.
- `registry/licences.json` requires a notice for the Unicode License v3, the licence of the
  Unicode Character Database script modules draw on. `registry/ilm/` keeps its source's GPL-2.0.

## 0.2.0

- Language modules. A language is a folder under `modules/<node>/` with `module.json`, a port importing
  only `tajziya.api`, `data/SOURCES.json` and `reference/examples.json`. Modules are discovered by
  scanning, loaded by path, and used only when `registry/bindings.json` binds them.
- `tajziya accept`: one generic acceptance test for any module, in isolation (A1 to A5) and bound in a
  scratch copy of the repository (A6).
- `tools/langpack.py`: generates a hand-over package for any node, any ISO 639-3 code, or every remaining
  node. Each package passes the acceptance test as handed over, and archives are reproducible.
- Classical Sanskrit moved into `modules/cls` as the reference module. Its sutra text is re-sourced from
  vidyut-prakriya's MIT-licensed sutrapatha, all 3,983 sutras; the restricted compilation is local-only.
- `registry/licences.json`: the licences data may carry. `registry/corpora.json`: Universal Dependencies
  treebanks matched to 52 nodes, each with its stated licence and whether the tree may carry it.
- The harness now exercises every layer declared built, including one with no reference input.
- `tools/node_new.py` removed; `tools/langpack.py` replaces it.
